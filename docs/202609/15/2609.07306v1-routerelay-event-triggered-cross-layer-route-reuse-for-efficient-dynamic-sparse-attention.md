## 摘要
动态稀疏注意力通过在每个 Transformer 层将每个查询块路由到一小组键块，降低长上下文预填充成本。稀疏注意力核避免了大多数 token 交互，但路由器仍会逐层重建块-块分数矩阵，即使所选路由变化很小。我们提出 RouteRelay，一种与路由器无关的方法：它跨深度仅复用路由元数据，同时继续使用当前层的查询、键和值计算注意力。锚层执行完整路由。中间层对先前的 top-k 路由以及一个紧凑的哨兵集合重新评分，该集合由接近入选的块和随机探测的块组成。仅当某个哨兵挑战查询行最弱的已选块时，该查询行才会被重新路由。我们给出了 top-k 稳定性条件、漏掉挑战者的概率界，以及一种行选择式 GPU 执行设计。在可复现的实证评估中，RouteRelay 在低、中、高跨层漂移下分别重新路由 25.0%、55.4% 和 78.2% 的行，同时保持至少 99.99% 的路由召回率。在不同路由规模下，随着键块数量从 128 增至 1024，RouteRelay 在评估完整路由分数对的 38.4--51.6% 的同时保持 100.0% 召回率。其未融合的 CPU 执行仍慢于稠密矩阵乘法，这暴露出行压缩和账本更新是主要的核工程优化目标。

## Abstract
Dynamic sparse attention reduces long-context prefill cost by routing each query chunk to a small set of key chunks at every Transformer layer. The sparse attention kernel avoids most token interactions, but the router still rebuilds a chunk--chunk score matrix layer after layer, even when the selected routes change little. We introduce RouteRelay, a router-agnostic method that reuses only route metadata across depth while continuing to compute attention with the current layer's queries, keys, and values. Anchor layers perform full routing. Intermediate layers rescore the previous top-$k$ route and a compact sentinel set of near-miss and randomly probed chunks. A query row is rerouted only when a sentinel challenges its weakest selected chunk. We give a top-$k$ stability condition, a probabilistic bound on missed challengers, and a row-selective GPU execution design. In a reproducible empirical evaluation, RouteRelay retains at least 99.99% route recall while rerouting 25.0%, 55.4%, and 78.2% of rows under low, moderate, and high cross-layer drift, respectively. Across routing scales, RouteRelay retains 100.0% recall while evaluating 38.4--51.6% of full-routing score pairs as the key-chunk count grows from 128 to 1024. Its unfused CPU execution remains slower than dense matrix multiplication, exposing row compaction and ledger updates as the main kernel-engineering targets.

## 1. 核心问题与整体含义
- **研究动机**：长上下文语言模型的预填充成本主要来自因果自注意力，其稠密计算随序列长度二次增长。动态稀疏注意力通过将每个 query chunk 路由到少量 key chunk 来减少 token 交互，但路由器仍需在每一层重新构建完整的 chunk–chunk 分数矩阵。
- **关键观察**：相邻 Transformer 层处理相同 token 位置，且常保留相似的语义依赖；即使路由选择变化很小，逐层重建完整路由矩阵仍造成重复计算。
- **整体含义**：论文提出 RouteRelay，一种与路由器无关的方法，只跨层复用“路由元数据”（整数 chunk ID），而不复用 KV 状态、注意力概率或输出。每一层仍用当前层的 Q、K、V 计算稀疏注意力，因此不改变浮点注意力数值，仅近似路由索引集合。
- **目标**：降低动态稀疏路由的重复开销，同时尽量保持 top-k 路由召回率，并通过事件触发和行级刷新适应跨层漂移。

## 2. 方法论
- **核心思想**：锚层执行完整路由并保存路由账本；中间层只对上一轮 top-k 路由和紧凑哨兵集合重新评分。仅当哨兵分数挑战了该行最弱的已选 chunk 时，才对该 query 行执行完整重路由。
- **路由账本**：每行保存 \(L_i^a=(R_i^a,C_i^a,a)\)，其中 \(R_i^a\) 是锚层选中的 top-k chunk，\(C_i^a\) 是哨兵集合，\(a\) 是锚层年龄。
- **哨兵集合**：
  - \(m\) 个紧邻 top-k 截止线的高分“近失”块；
  - \(r\) 个均匀采样的被忽略块；
  - 强制全局候选，如 attention sink 和最近块。
- **候选重评分**：中间层只评估 \(A_i^\ell=R_i^a\cup C_i^a\)。定义已选块最低分 \(\alpha_i^\ell=\min_{j\in R_i^a}S_{ij}^\ell\)，哨兵最高分 \(\beta_i^\ell=\max_{j\in C_i^a}S_{ij}^\ell\)。若 \(\alpha_i^\ell>\beta_i^\ell+\gamma_i\)，则复用原路由；否则该行执行完整 \(n_k\) 分数计算并重建路由与哨兵。刷新在行和层之间异步发生。
- **稳定性分析**：若锚层 margin \(\Delta_i^a=\min_{j\in R_i^a}S_{ij}^a-\max_{j\notin R_i^a}S_{ij}^a>2\epsilon_i\)，且层间分数扰动不超过 \(\epsilon_i\)，则 top-k 路由不变。该条件是充分条件，主要用于分析。
- **随机哨兵漏检概率**：若残差池大小 \(N\)，有 \(u\) 个遗漏块变得有竞争力，随机无放回采样 \(r\) 个哨兵，漏掉全部挑战者的概率为  
  \(P_{\text{miss}}=\binom{N-u}{r}/\binom{N}{r}\le(1-u/N)^r\)。
- **复杂度**：完整动态路由 \(T_{\text{full}}=O(n_q n_k d)\)；RouteRelay 为  
  \(T_{\text{relay}}^\ell=O(n_q(k+m+r)d+\rho^\ell n_q n_k d)\)，其中 \(\rho^\ell\) 是刷新行比例。
- **系统设计**：维护行主序张量，包括路由、哨兵和锚年龄；用批处理评分候选，前缀和压缩不稳定行 ID，第二 kernel 只对刷新子集计算完整分数并更新账本。支持 hysteresis、强制锚层、按路由宽度分桶和内存估算。
