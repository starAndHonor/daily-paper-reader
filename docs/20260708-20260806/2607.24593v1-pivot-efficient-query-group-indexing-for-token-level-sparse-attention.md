## 摘要
生产系统中的DeepSeek稀疏注意力（DSA）所实现的Token级稀疏注意力，使得下游注意力计算高效，但将瓶颈转移到了为它提供输入的索引器上。为了为每个查询选择top-k令牌，索引器仍然需要对每个先前的令牌进行评分，对于一个长度为L的序列，每层会产生O(L^2)的成本。我们观察到这种逐查询扫描在很大程度上是冗余的：邻近的查询选择高度重叠的top-k令牌，并且索引器的评分在键（key）维度上呈长尾分布。我们在PIVOT（Proxy Indexing Via One full-prefix Traversal，通过一次全前缀遍历的代理索引）中利用这些特性，这是DSA索引器的一种无需训练、可直接替换的替代方案，它在一组邻近查询之间共享一次前缀扫描。PIVOT将一组查询聚合为一个代理查询，执行一次共享的全前缀扫描以获得候选集，然后从该集合中为每个查询选择top-k。两种变体在速度和保真度之间进行权衡：PIVOT-Reuse在组内共享代理top-k以获得最大速度，而PIVOT-Refine使用每个查询的索引器对候选集重新评分，然后选择各自的top-k，以少量额外成本匹配密集索引器。一个统一的算法覆盖了两个推理阶段，仅在组的形成方式上不同：在预填充（prefill）阶段，连续查询的固定大小组；在解码（decode）阶段，一次多令牌预测（MTP）步骤中一起解码的查询。在DeepSeek-V3.2和GLM-5.1上，跨LongBench和RULER基准测试，PIVOT在匹配密集DSA索引器准确性的同时，将其加速高达4倍，并在长上下文中将端到端延迟降低高达1.6倍。

## Abstract
Token-level sparse attention, as implemented by DeepSeek Sparse Attention (DSA) in production systems, makes the downstream attention efficient but shifts the bottleneck to the indexer that feeds it. To select the top-k tokens for each query, the indexer must still score every preceding token, incurring a cost of O(L^2) per layer for a sequence of length L. We observe that this per-query scan is largely redundant: nearby queries select highly overlapping top-k tokens, and the indexer scores are long-tailed along the key axis. We exploit these properties in PIVOT, Proxy Indexing Via One full-prefix Traversal, a training-free, drop-in replacement for the DSA indexer that shares one prefix scan across a group of nearby queries. PIVOT aggregates a group into a single proxy query, performs one shared full-prefix scan to obtain a candidate set, and then selects a top-k for each query from that set. Two variants trade speed for fidelity: PIVOT-Reuse shares the proxy top-k across the group for maximum speed, whereas PIVOT-Refine re-scores the candidate set with the indexer of each query and then selects an individual top-k, matching the dense indexer at a small additional cost. A single algorithm covers both inference phases, differing only in how groups are formed: fixed-size groups of consecutive queries in prefill, and the queries decoded together in one multi-token prediction (MTP) step in decode. On DeepSeek-V3.2 and GLM-5.1 across LongBench and RULER, PIVOT matches the accuracy of the dense DSA indexer while accelerating it by up to 4x and reducing end-to-end latency by up to 1.6x at long context.

## 1. 论文的核心问题与整体含义（研究动机和背景）

- **背景**：随着大语言模型上下文窗口向百万级token扩展，长上下文推理成为核心挑战。DeepSeek Sparse Attention（DSA）作为生产级Token级稀疏注意力方案，通过轻量级索引器为每个查询选择top-k最相关的历史token，将主注意力计算从O(L²)降至O(Lk)，显著减轻了下游注意力算力负担。
- **核心问题**：DSA的优化只是**转移**了瓶颈——索引器本身仍是稠密的，必须为每个查询逐一对整个前缀进行评分，每层产生O(L²)的计算开销（Prefill阶段约占端到端延迟81%，Decode约占41%，@200K tokens）。随着上下文增长，索引器从可忽略的预处理步骤变成了主导成本，严重制约长上下文推理效率。
- **PIVOT 的整体含义**：本文识别出DSA索引器沿查询轴存在巨大的跨查询冗余——邻近查询选择的top-k token高度重叠，且索引器分数沿key轴呈长尾分布。据此提出PIVOT，将一组邻近查询聚合为一个代理查询，共享一次前缀扫描，从根本上避免了逐查询重复遍历。该工作新增了与token轴、head轴、layer轴正交的**第四条效率优化轴向**（query轴），为稀疏注意力索引器优化提供了全新视角。

## 2. 方法论：核心思想、关键技术细节、公式与算法流程

### 2.1 核心思想
PIVOT基于三个实证观察（图2）：
- **O1 邻近查询高度重叠**：相邻查询的top-k集合重叠率约0.8–0.9，一个g=4的组中位数共享65–78%的top-k，从浅层到深层成立。
- **O2 组的top-k并集很小**：g=4时并集仅约为1.3–1.5×k，g=16时增长到1.7–2.4×k，远低于最坏情况g·k，远小于前缀长度L。
- **O3 索引器分数长尾分布**：分数集中在一小部分"活跃"token上，累计质量曲线在远低于k的位置就趋近饱和。

这三个性质互补：O1使共享成为可能，O2使共享高效，O3保证重排精度。

### 2.2 DSA索引器公式（待优化对象）
$$
I_{t,s} = \sum_{j=1}^{H_I} w^I_{t,j} \operatorname{ReLU}\left(q^I_{t,j} \cdot k^I_s\right)
$$
每个查询必须对所有前缀token s≤t计算该分数，导致O(L²)成本。

### 2.3 PIVOT 核心算法流程

**分组（Grouping）**：
- **Prefill阶段**：将序列所有可用的查询位置划分为连续固定大小组，每组g个查询（默认g=4）。
- **Decode阶段**：利用多token预测（MTP）机制，将当前token与其d个draft token（d=3，共g=d+1=4）聚合为一组，无需额外开销。

**共享代理扫描（Coarse Step）**：
- 对组内各查询的索引query和门控权重做逐头平均，得到代理查询：
$$
\bar{q}^I_j = \frac{1}{g}\sum_{t'\in G} q^I_{t',j}, \quad \bar{w}^I_j = \frac{1}{g}\sum_{t'\in G} w^I_{t',j}
$$
- 代理查询对前缀执行**一次**全量扫描（以组首位置为因果截止点），计算代理分数：
$$
\bar{I}_s = \sum_{j=1}^{H_I} \bar{w}^I_j \operatorname{ReLU}\left(\bar{q}^I_j \cdot k^I_s\right)
$$

**两种变体（Fine Step）**：
- **PIVOT-Reuse（快速版本）**：跳过细粒度步骤，直接将代理top-k分配给组内每个查询。复杂度从O(gL)降至O(L)。组大小为1时退化为原始DSA。
- **PIVOT-Refine（高保真版本）**：从代理分数中取top-c作为共享候选集C（c=2k=4096），然后每个查询用**精确索引器**在C上重新评分并选择各自的top-k。复杂度为O(L+gc)，介于Reuse和DSA之间。
- **局部窗口**：候选集C与每个查询最近W个token的局部窗口取并集，确保组内成员不丢失最近的局部上下文（W=4，Prefill中预留W+g−1个槽位）。

**短序列保护**：当组首位置不足c时，PIVOT回退为DSA稠密扫描，确保部署时不会慢于基线。PIVOT保持Tt作为与Sparse MLA的唯一接口，下游算子与KV缓存完全不变。

## 6. 主要结论与发现

1. **PIVOT匹配稠密索引器精度**：在DeepSeek-V3.2和GLM-5.1的LongBench和RULER上，PIVOT-Refine在各长度档位均与DSA密集索引器精度持平，平均几乎无损失。

3. **速度-保真度权衡清晰**：Reuse更快但长上下文精度下降，Refine以少量额外开销换取接近DSA的精度，两者构成明确的操作区间。

5. **单算法统一两个推理阶段**：Prefill按固定组，Decode搭MTP便车，两种变体与IndexCache等正交方法可组合。

## 8. 不足与局限

- **上下文尺度有限**：精度实验最长到128K（RULER），效率实验到256K，尚未覆盖百万级token的极端长上下文场景。
