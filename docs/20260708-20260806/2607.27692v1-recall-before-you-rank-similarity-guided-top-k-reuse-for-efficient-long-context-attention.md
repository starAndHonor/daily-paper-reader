## 摘要
Top-$K$稀疏注意力通过仅关注一小部分键-值（KV）条目来降低Softmax和值聚合的计算成本。然而，识别这一子集仍需要将当前查询与完整KV缓存进行评分并执行全局Top-$K$选择，这使得选择器的成本随上下文长度线性增长，限制了稀疏注意力在长上下文解码中的实际效率。本文提出ReTopK，一种无需训练的方法，通过复用历史检索决策来加速动态Top-$K$注意力。ReTopK基于以下观察：相似的查询往往关注重叠的支持集，且部分重叠的支持集仍能保留大部分精确Top-$K$注意力的质量。对于每个注意力头，它维护一个有界的查询-支持对历史缓存，为每个新查询检索最相似的缓存查询，将其存储的支持集与近期窗口取并集，并仅使用精确的当前查询分数对生成的紧凑候选集进行重新排序。当复用不可靠时，基于相似性的回退机制会调用全历史精确Top-$K$，而定期精确刷新则限制缓存漂移。ReTopK保留完整KV缓存，仅复用选中的索引，而非历史分数、注意力权重或输出。在16K--128K上下文范围内，ReTopK在评估的近似方法中取得了最低的PG19困惑度以及最高的NIAH和LongBench分数。在128K且$K=512$时，ReTopK相对于精确Top-$K$仅增加0.50\%的困惑度，同时将注意力计算加速了$3.07\times$。

## Abstract
Top-$K$ sparse attention reduces the cost of Softmax and value aggregation by attending to only a small subset of key--value (KV) entries. However, identifying this subset still requires scoring the current query against the full KV cache and performing global Top-$K$ selection, leaving selector cost linear in context length and limiting the practical efficiency of sparse attention for long-context decoding. In this paper, we introduce ReTopK, a training-free method that accelerates dynamic Top-$K$ attention by reusing historical retrieval decisions. ReTopK builds on the observation that similar queries often attend to overlapping supports and that partially overlapping supports can still preserve most of the Exact Top-$K$ attention mass. For each attention head, it maintains a bounded cache of historical query--support pairs, retrieves the most similar cached queries for each new query, unions their stored supports with a recent window, and reranks only the resulting compact candidate set using exact current-query scores. A similarity-based fallback invokes full-history Exact Top-$K$ when reuse is unreliable, while periodic exact refreshes limit cache drift. ReTopK retains the complete KV cache and reuses only selected indices, rather than historical scores, attention weights, or outputs. Across 16K--128K contexts, ReTopK achieves the lowest PG19 perplexity and the highest NIAH and LongBench scores among the evaluated approximate methods. At 128K with $K=512$, ReTopK incurs only a 0.50\% perplexity increase over Exact Top-$K$ while accelerating attention computation by $3.07\times$.

## 1. 论文的核心问题与整体含义（研究动机和背景）

- **背景**：大语言模型（LLM）在长文档、代码库、长对话等场景中，解码时的注意力计算成本随 KV 缓存长度线性增长。虽然 FlashAttention 等 IO 感知内核提升了硬件效率，但并未消除注意力对上下文长度的线性依赖。
- **核心问题**：Top-K 稀疏注意力虽将 Softmax 与值聚合限制在 K 个最高分词项上，但**选择这 K 个索引本身仍需对完整 KV 缓存进行全量 QK 评分与全局 Top-K 选择**——即"稀疏化了聚合，却没有稀疏化索引发现"。随着上下文增长（16K→128K），全历史 QK 评分和 Top-K 选择在精确 Top-K 注意力延迟中占比从 58.8% 升至 95.6%，成为主要瓶颈（图 1a）。
- **研究问题**：能否让动态选择器在不逐解码步扫描全部历史的前提下，恢复查询特定的注意力支持集（attention support）？
- **核心观察**：相似的查询往往产生重叠的 Top-K 支持集；即便支持集只部分重叠，也能保留大部分精确 Top-K 注意力质量。这为复用历史检索决策提供了依据。

## 2. 论文提出的方法论（ReTopK）

### 核心思想：Recall-Before-Rerank（先检索、后重排）
ReTopK 是一种**无需训练**的方法，通过复用历史检索决策来加速动态 Top-K 注意力。它仅复用历史的**索引选择**，不复用历史 QK 分数、注意力权重或输出。

### 技术流程（按注意力头独立维护）

1. **查询-支持缓存（Query–Support Cache）**
   - 每个注意力头维护一个有界 FIFO 缓存，容量为 C，存历史归一化查询向量及其对应的 Top-K 支持索引集：$\mathcal{B}_t = \{(\bar{q}_c, \hat{S}_c)\}$。
   - 缓存仅增加 O(Cd + CK) 的元数据开销，完整 KV 缓存保持不变。

2. **相似性引导的召回（Similarity-Guided Recall）**
   - 对当前归一化查询 $\bar{q}_t$，计算其与全部缓存查询的余弦相似度：$\rho_{t,c} = \bar{q}_t^\top \bar{q}_c$。
   - 选取最相似的 R 个缓存查询，记录最大相似度 $\rho_t^{max}$。
   - 召回复杂度为 O(Cd)，与上下文长度 Lt 无关，而非 Exact Top-K 的 O(Ltd)。

3. **候选集构建（Candidate Construction）**
   - 将 R 个检索到的历史支持集取并集，并与一个近期窗口（最近 W 个 token）合并，得到紧凑候选集 $\mathcal{A}_t$，其大小 $M_t \le RK + W \ll L_t$。
   - 近期窗口保证新加入的 token 即使不在历史支持集中也可被纳入候选。

4. **精确重排（Exact Reranking）**
   - 仅对候选集中的键计算当前查询的精确 QK 分数：$\hat{e}_{t,i} = q_t^\top k_i / \sqrt{d}$。
   - 在候选集内重新执行 Top-K 选择得到最终支持集 $\hat{S}_t$。
   - 若真实支持 $S_t \subseteq \mathcal{A}_t$，重排可精确恢复 $S_t$。

5. **可靠复用机制（Fallback & Refresh）**
   - **相似性回退**：当最大缓存查询相似度 $\rho_t^{max} < \tau$ 时，说明没有足够可靠的近邻，回退到全历史 Exact Top-K。
   - **周期性刷新**：每 Tr 个解码步强制执行一次 Exact Top-K，将精确支持插入缓存，限制长时漂移。
   - 路径选择规则：$P_t = \text{Exact}$（若 Tr 周期到或相似度低于阈值），否则 $\text{Reuse}$。

6. **GPU 实现**：三段式融合内核——融合选择器（缓存匹配 + Top-R 检索 + 候选排序去重）→ 索引式 QK 内核（直接对打包候选键打分，免去键收集）→ 融合内核（候选 Top-K 选择 + 索引式 Softmax-值聚合 + 缓存更新）。

## 6. 论文的主要结论与发现

1. **质量-效率平衡优异**：在 128K 上下文、K=512 时，ReTopK（τ=0.85）仅比 Exact Top-K 高 0.50% PPL，注意力计算加速 3.07×；τ=0.90 时加速 1.14–2.25×，且在 NIAH 所有长度上领先所有近似方法，LongBench 得分（52.7）甚至超过 Exact Top-K（52.5）。
2. **跨模型泛化良好**：同一组参数直接迁移到 Llama-3.1-8B 与 Qwen2.5-14B，在 82.5–89.6% 复用率下 PPL 变化仅 -0.46% 至 +2.76%，加速 1.26–2.66×。
3. **支持保真度解释**：虽然 ReTopK 的 Top-K 支持召回率仅 56.9%，但保留 92.4% 的注意力质量、97.4% 的 head 输出余弦——说明未匹配的索引获得的是极低的归一化注意力权重，对输出影响甚微。

5. **瓶颈随上下文转移**：Exact Top-K 中 QK 评分与选择占比从 16K 的 87% 升至 128K 的 97%；ReTopK 的复用路径成本近似恒定，端到端加速比从 128K 的 1.13× 升至 5M 的 3.73×，上下文越长优势越明显。

## 7. 优点

- **问题定位精准**：明确指出 Top-K 稀疏注意力"稀疏化聚合但未稀疏化索引发现"的盲区，并给出量化的延迟分解证据。

## 8. 不足与局限

- **对比公平性存疑**：Loki 在共享 K=512 预算下处于劣势配置（其设计假设更大预算），StreamingLLM 本质上牺牲了长程检索能力；部分基线在小上下文下的速度退化（如 SparQ 0.51×）未充分解释。
- **实验覆盖有限**：LongBench 仅使用 3 个子集；未在更大模型（如 70B 级）或更多模型家族（如 Mistral、DeepSeek）上验证；未与最新索引复用方法（Kascade、IndexCache、PRR）直接对比。
- **质量-速度权衡依赖阈值**：τ 和 Tr 需要取舍，τ=0.85 虽然加速好但 NIAH 128K 得分（53.3）明显低于 τ=0.90（75.2），说明默认配置在极端上下文下可能牺牲较多检索质量；对敏感任务需调整参数。
- **自回归误差分析的广度有限**：长时稳定性实验仅用 8 个文档、8K 延续，样本量较小；KL 散度与 Top-1 一致性虽稳定，但未评估生成文本的语义质量。
- **缓存元数据开销未完全透明**：虽为 O(Cd + CK) 每头，但在 28 层 × 多头下具体的内存增量、对长上下文的相对占比未量化。
- **理论保证缺失**：没有提供支持复用覆盖率或误差上界的理论分析，依赖经验观察；候选集大小 $M_t \le RK + W$ 的上界是确定的，但覆盖率随数据分布波动。
