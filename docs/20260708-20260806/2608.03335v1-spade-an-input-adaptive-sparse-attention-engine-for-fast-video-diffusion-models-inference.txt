## Abstract 

Video diffusion transformers (vDiTs) generate high quality but pay quadratic self-attention cost, making inference prohibitive at video-token scales. The challenge is input-adaptive sparsity: se-lecting critical Q/K/V tokens with negligible overhead and execut-ing them for end-to-end gains. We present SPADE , a training-free sparse-attention engine of three parts: (i) vDiT-SSR , spec defin-ing 3D blocking candidates and formalizing dynamic masks via 

Summarizer /Estimator expressions; (ii) runtime scheme gener-ation using SICS and a head-wise policy; and (iii) an executor with low-overhead index search, flash block-sparse attention, and kernel grouping. Across Hunyuan-Video, Wan 2.1/2.2 (T2V/I2V), 

SPADE raises sparsity and speed and preserves quality, accelerating attention 2.26 ×–3.40 × and end-to-end 1.49 ×–1.80 ×. Our code is open-sourced at https://github.com/6somehow/DAC-SPADE.

## 1 Introduction 

Video generation has become a core generative-AI task. Modern sys-tems—Sora [ 18 ], Veo [ 9 ], Wan [ 23 ], Hunyuan-Video [ 13 ]—typically use Video Diffusion Transformers (vDiTs) with self-attention. At-tention scales as O( 𝑛 2) in compute ; naive memory is also O( 𝑛 2),while streaming (FlashAttention) reduces memory to O( 𝑛 ) but leaves compute quadratic and the main latency source [ 5 ]. In video DiTs, the 3D token grid aggravates both compute and traffic. Much of this cost is redundant [ 6, 12 , 27 ], motivating sparse attention for video [2, 7, 21, 25, 28, 29, 33].

We group sparse attention for video into: i) Static —fixed 3D blocking/sliding windows (e.g., Fast-VideoGen [ 34 ]); efficient but not adaptive. ii) Semi-static —pick among a few predefined patterns (e.g., Sparse-VideoGen [ 25 ]); mildly adaptive, but search space is tiny. iii) Dynamic —input-conditioned without a preset mask (e.g., Sparge Attention [ 32 ]); flexible but with control/indexing overhead. The aim is higher sparsity and throughput without quality loss, yet most systems optimize one aspect in isolation. Progress toward near-linear scaling remains limited: sparsity gains are modest, and wall-clock speedups lag (Table 1). Combining static , semi-static , and dynamic methods can raise sparsity but adds overhead, creating end-to-end challenges: (i) Blocking scheme selection. Choosing an input-conditioned 3D blocking from many candidates with negligible cost is nontrivial. 

(ii) Efficient dynamic kernels. Dynamic patterns improve adap-tivity and sparsity but add control/indexing overhead, demanding hardware-aware kernels (accelerator instructions, fusion, access-aware design) and user customizability. (iii) Multi-granularity control. Token importance varies by head/layer/timestep [ 1 , 2,16 , 32 ]; exploiting this heterogeneity to increase sparsity while preserving quality remains hard. We present SPADE , a training-free, algorithm–systems co-designed framework for high-performance hybrid-sparse attention. First, the Video DiT Sparsity Scheme Representation (vDiT-SSR) is a uni-fied interface spanning all three families, enabling flexible high-sparsity hybrids. vDiT-SSR expresses: (i) diverse 3D static blocking via blocking-scheme candidates ; (ii) dynamic block-index selection via summarizer /estimator expressions; and (iii) automatic sparsity control via policy-function interfaces. Built on vDiT-SSR, SPADE accelerates inference via two mod-ules: (1) Scheme Generation : fast, input-adaptive, head-wise/per-timestep patterns using the online Sum of Intra-block Cosine Simi-larities (SICS) with a lightweight policy that budgets across timesteps/layers; arXiv:2608.03335v1 [cs.CV] 4 Aug 2026 DAC ’26, July 26–29, 2026, Long Beach, CA, USA Liu et al. 

and (2) Head-wise Sparse Attention : an execution engine (code-gen + library) that groups kernel launches, fuses QKV index-selection, and implements hardware-aware flash block-sparse attention for high-throughput adaptive computation. We validate on T2V/I2V with Hunyuan-Video, Wan 2.1, and Wan 2.2. Compared to strong sparse baselines, SPADE preserves quality (VBench [ 11 ], PSNR/SSIM/LPIPS) while achieving the high-est sparsity and lowest latency. On an NVIDIA H800 at 720p, atten-tion speedups are 2.26 ×–3.40 × and end-to-end gains 1.48 ×–1.70 ×.In summary, our contributions are: 

• vDiT-SSR. A unified, expressive module integrating 3D block-ing candidates with dynamic selection (summarizer/estimator), subsuming prior designs and enabling new hybrids. 

• Scheme Generation. A head-wise, input-adaptive generator using online SICS plus a lightweight policy. Scheme generation is 8% of sparse-attention runtime yet yields higher sparsity than alternatives. 

• Head-wise Sparse Attention Execution. Lowering vDiT-SSR to block-sparse kernels via codegen/library with low-cost index selection, kernel grouping, and hardware-aware optimizations. At equal sparsity, pattern search is 3.48 × faster and computation 

1.80 × faster than state-of-the-art kernels. 

• End-to-end gains. On Hunyuan-Video and Wan 2.1/2.2 for T2V/I2V, 

SPADE speeds attention by 2.26 ×–3.40 × and end-to-end by 1.49 ×–

1.80 ×, while matching or improving generation quality.

## 2.3 Taxonomy of Sparse Attention 

To target critical blocks in long-text and video, we group prior sparse attention into three classes. 

Static methods use input-agnostic masks (Attention Sink [ 27 ], DiTFastAttn [ 30 ], Fast-VideoGen [ 34 ]). Fixed windows are simple and efficient but assume local stationarity and cannot adapt to content. 

Semi-static methods choose among predefined masks per head using the input (DuoAttention [ 26 ], DiTFastAttnV2 [ 31 ], Sparse-VideoGen [ 25 ]). They add limited adaptivity; mask selection can be inefficient or hurt accuracy. 

Dynamic methods generate masks from the input (ArkVale [ 3], FlexPrefill [ 14 ], SeerAttention [ 8], Sparge Attention [ 32 ]). These often preserve quality with less compute, but mask construction adds overhead that degrades end-to-end latency. 

## 3 Methodology 

We introduce the SPA rse video DiT Engine (SPADE), a sparse-attention engine for vDiTs (Figure 2). SPADE has three components. Let the head dimension be 𝑑 ℎ𝑒𝑎𝑑 ; Q, K, V the inputs and O the output; BS the block size and NB the number of blocks. 

(a) Video DiT Sparsity Scheme Representation (vDiT-SSR). 

vDiT-SSR is an input spec for fine-grained sparsity. It lists blocking scheme candidates and a policy function for head-wise scheme gen-eration, plus a Summarizer Expression and an Estimator Expression 

that formalize dynamic sparse attention. 

(b) Schemes Generation. Given Q, K, and the inference state, this module performs Aggregation Evaluation using the Sum of Intra-block Cosine Similarities (SICS), then applies the policy to yield each head’s sparsity-ratio scheme and blocking scheme .

(c) Head-wise Sparse Attention. This is the compute core: ahead-of-time compiled operators implementing the vDiT-SSR al-gorithm, including flash block-sparse attention and head-wise Top-K/Top-P selection. At runtime it consumes Q, K, V and the head-wise schemes to produce O.

After aggregation, SPADE selects the per-head Selected Blocking Scheme (max AS). The Selected Aggregation Score and the inference state then feed the policy function to produce each head’s sparsity-ratio scheme , enabling fine-grained control over static vs. dynamic sparsity and overall levels. 

## 3.3 Head-wise Sparse Attention 

The performance core of SPADE is a highly optimized Head-wise Sparse Attention pipeline (Figure 2c). Per head, Q, K, V are first re-arranged into a blocked layout by the Selected Blocking Scheme for intra-block contiguity. The Summarizer Expression then produces one vector per Q/K block, yielding summaries 𝑄 ′ and 𝐾 ′ of shape (𝑁 𝑏𝑙𝑜𝑐𝑘𝑠 , 𝑑 ℎ𝑒𝑎𝑑 ). From 𝑄 ′/𝐾 ′, we compute (i) intra-block importance 

(one score per block) via the intra-estimator and (ii) an inter-block importance matrix of size 𝑁 𝑄 𝑏𝑙𝑜𝑐𝑘𝑠 × 𝑁 𝐾 𝑏𝑙𝑜𝑐𝑘𝑠 via the inter-estimator. Scores are filtered by Top-K or Top-P. SPADE supports arbitrary combinations of intra/inter importance; by default, intra scores are broadcast and OR -combined with inter scores. The result is united with local-window and attention-sink masks to form a binary atten-tion mask defining the block-sparse pattern. block-sparse attention kernel computes the main operation, after which output blocks are restored to the original layout to form 𝑂 .We apply three throughput optimizations. (1) Operator fusion. 

We fuse layout transform (blocking), summarization, and intra-estimation into one CUDA kernel, reducing global traffic, improv-ing locality, and reusing on-chip memory. (2) Head grouping. At runtime, SPADE groups heads sharing a blocking scheme to in-crease per-launch work and utilization; this also lets us fuse Q/K gather–scatter with the layout transform, consolidating memory accesses. (3) Flash block-sparse attention. Inspired by FlashAt-tention [ 4, 5 , 19 , 20 ] and sparse variants [ 10 , 22 ], our kernel (i) preprocesses the mask into ranked BSR for sequential access, (ii) uses an online softmax to avoid materializing dense attention, and (iii) exploits Hopper features (Tensor Memory Accelerator, warp-group MMA) to pipeline memory/compute. Heads with identical sparsity patterns are co-scheduled to raise overall utilization. 

## 4 Experiments 4.1 Experimental Setup 

Models: We evaluate five open-source vDiTs: Wan 2.1-I2V/T2V-14B, Wan 2.2-I2V/T2V-14B, and Hunyuan-Video-T2V-13B. Videos are 720p. Wan 2.1/2.2 output 61 frames; Hunyuan-Video-T2V outputs 125. Each frame has 3600 tokens. 

Metrics: We report three dimensions: Sparsity —fraction of pruned attention scores (theoretical speedup upper bound); Effi-ciency —attention TFLOPs, attention-level speedup, and end-to-end speedup vs. full attention; Quality —VBench [ 11 ] plus fidelity to full attention (SSIM/PSNR/LPIPS). 

Datasets: Text-to-Video uses VBench-2.0 prompts [ 35 ] across 18 categories, with versions for Wan 2.1, Wan 2.2, and Hunyuan-Video. Image-to-Video uses VBench-2.0-I2V pairs [ 35 ], cropped to 16:9 for 720p. 

Configurations: All experiments run on an NVIDIA H800 (80GB, CUDA 12.8). Two fixed inference-time policies: Func 0 (Wan 2.1/2.2) budgets 30:1 for dynamic selection vs. static windows; Func 1 

(Hunyuan-Video) budgets ∼80% dynamic, 20% static. Dynamic se-lection follows SPADE (Figure 4a): Summarizer and inter-estimator inputs; intra-block SICS; inter-block Top-K; intra-block threshold-ing. 

Baselines: We compare Full Attention via FlashAttention-3 [ 19 ]; semi-static Sparse-VideoGen [25 ]; and dynamic Sparge Attention [32 ], X-Attention [28 ], Sparse-VideoGen2 [ 29 ]. X-Attention selects anti-diagonal (“slash”) scores; Sparse-VideoGen2 uses k-means to form the mask. Defaults are used. X-Attention is incompatible with Wan 2.1/2.2 and Sparse-VideoGen2 with Wan 2.2, so these are omitted. Following [ 15 , 17 , 25 , 29 ], all methods use full attention for the first 30% (T2V) and 25% (I2V) denoising steps; 

SPADE-Turbo sparsifies after the first step. 

## 4.2 Overall Performance 

Table 2 summarizes results. 

Sparsity. SPADE achieves the highest sparsity on every model (82.32%–85.21% ), exceeding prior baselines (47.10–83.80%). SPADE-Turbo matches SPADE’s sparsity. 

Efficiency. Despite higher sparsity, SPADE’s kernels are most ef-ficient: attention speedups 2.26 ×–3.44 × and end-to-end 1.32 ×–1.49 ×, with the highest attention TFLOPs among dynamic baselines. 

SPADE-Turbo further raises end-to-end speedup to 1.49 ×–1.80 × at the same sparsity. 

Quality (Overall + Fidelity). SPADE matches or surpasses base-lines on perceptual quality: VBench is comparable to full atten-tion (0.76–0.81); SPADE-Turbo reaches 0.79 (Hunyuan-Video-T2V) and 0.75 (Wan 2.2-I2V). For fidelity, SPADE leads on Wan 2.1/2.2 (T2V/I2V) with higher SSIM/PSNR and lower LPIPS, and remains competitive on Hunyuan-Video-T2V (within 0.01 SSIM of the best sparse baseline).
