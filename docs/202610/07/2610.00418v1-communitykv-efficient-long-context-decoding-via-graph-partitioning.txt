# Abstract 

Scaling Transformers to long contexts is constrained by the quadratic cost of self-attention and the linear growth of key-value cache memory transfer. Sparse attention mitigates this by retrieving only relevant tokens, but current approaches either require large-scale training or, within the training-free regime, rely on seman-tically coarse heuristics or expensive clustering that is difficult to update efficiently during decoding. We introduce CommunityKV, a framework that formulates sparse attention as a community detection problem. CommunityKV constructs a token graph from the QK T scores already computed during standard prefill, and par-titions the graph into communities to enable retrieval of semantically coherent token groups. A local update rule assigns newly generated tokens to communities in constant time, enabling sparse retrieval throughout streaming decoding with-out global re-partitioning. We evaluate CommunityKV on Qwen3 and Llama-3.1 models across three long-context benchmarks. With one graph per query head, CommunityKV delivers up to 1.25 × the end-to-end generation throughput of dense attention, while query-group graph aggregation yields up to 1.71 × with comparable accuracy. 

# 1 Introduction 

The capacity for Transformers [40] to process long context inputs powers a new generation of applications, ranging from repository-level code understanding [2, 32] and long-horizon agentic planning [10] to multimodal reasoning [42]. However, as the context length grows, standard self-attention encounters prohibitive bottlenecks: the quadratic cost of attention and the linear growth of key-value (KV) cache memory transfer. Despite the increasing KV cache size for modern applications, empirical studies demonstrate that token prediction accuracy is driven by only a small fraction of relevant past tokens [51, 13]. Sparse attention methods attempt to exploit this redundancy by loading only a portion of the KV cache at each generation step [38, 28]. Recent architectural methods such as DeepSeek Sparse Attention [8] integrate sparsity into the training objective, but require large-scale training. Within the training-free regime, current approaches force a compromise: they either employ retrieval heuristics that suffer from unacceptable accuracy degradation [37] or rely on heavy preprocessing of the KV cache that is difficult to update during decoding [16]. In this work, we propose CommunityKV, a framework that formulates training-free sparse attention as community detection on a graph induced from attention scores. CommunityKV leverages the structure already present in the QK ⊤ matrix to identify semantically coherent token groups. A local

Our contributions are as follows: • Formulation: We formulate sparse attention as community detection on a token graph induced from QK ⊤ scores. # 2 Related work 

Architectural vs. training-free sparse attention Recent methods integrate sparsity directly into the training objective, achieving large throughput gains. DeepSeek Sparse Attention (DSA) [8] scores queries against lightweight indexer keys to select a top-k subset of past tokens for full attention, while Native Sparse Attention (NSA) [48] combines block-level token compression with fine-grained token selection. However, these approaches couple sparsity to model training: the upfront cost amortizes only at very high inference volumes, and the resulting sparsity pattern is fixed at training time, limiting retrieval quality to the training distribution. CommunityKV targets the complementary setting: training-free sparse attention. Within the training-free regime, existing approaches reduce KV cache traffic via two strategies. KV cache compression methods [51, 23, 26] enforce strict memory ceilings through token eviction or merging, but are inherently lossy: once discarded, information cannot be recovered. Selective retrieval methods instead preserve the full KV cache in memory and dynamically load only relevant tokens at each decoding step. The effectiveness of retrieval-based methods depends on the design of the sparsity mask, which typically employs either fixed or dynamic patterns. 

Fixed-pattern sparse attention Early work on sparse attention relied on predefined, query-independent sparsity patterns. The Sparse Transformer [6] introduced factorized attention with strided patterns, achieving sub-quadratic O(n√n d ) complexity. Longformer [3] and BigBird [49] combined sliding windows, dilated patterns, and global tokens to achieve linear O(nd ) complexity. LongNet [9] extended dilated attention to billion-token sequences, and StreamingLLM [46] showed that retaining initial “attention sinks” stabilizes sliding window attention. Because these patterns are fixed in advance, they miss relevant tokens that fall outside the predefined structure. 

Dynamic sparse attention Dynamic sparse attention frames the problem as query-dependent retrieval, typically using auxiliary data structures to index the KV cache and select relevant subsets at each step. A first family uses heuristics over contiguous token blocks. Quest [37] tracks channel-wise min-max values to estimate query-key overlap, while a similar training-based method MoBA [27] applies block-wise gating to filter context chunks. These methods avoid heavy auxiliary data structures but treat blocks of contiguous tokens as the retrieval unit: a high-scoring outlier within a block triggers retrieval of the entire block, including unrelated neighbors. A second family uses Locality Sensitive Hashing [19, 50, 5, 15] to bucket tokens using random projections. The result is a compressed cache that every subsequent decoding step queries against. CommunityKV adopts the opposite philosophy. Instead of treating semantic similarity as a signal to be decayed, we treat it as the basis for community formation: we retain the full KV cache and dynamically retrieve communities for each query, allowing the model to access locally dense semantic structure without permanently deleting context. 

# 3 Method

Theoretical justification The combined graph w admits a dynamical interpretation that motivates graph partitioning, grounded in the mathematical structure of self-attention. Because α is row-stochastic, it defines the one-step transition kernel of a discrete Markov chain over the token sequence. Symmetrizing as (α + α⊤)/2 and combining with the second-order affinity matrix α⊤α yields a symmetric kernel of a time-reversible random walk, and sparsifying via top-κ selection produces w,preserving the dominant transition paths with bounded sparsity ( E = O(n)). In this framework, token communities correspond to metastable states of the walk: groups of tokens the walk is unlikely to escape over time. We partition the graph into these communities by maximizing modularity [29], which on the symmetric graph defined by w is equivalent to maximizing the linearized Markov Stability of the induced walk [21]. In practice, we employ the Leiden algorithm [39] to perform this graph partitioning.

3.4 Implementation 

We fuse top-κ selection into the FlashAttention QK main loop using a WarpSelect-style selector [18]. For each query row, GPU threads maintain small sorted candidate queues, updated via compare-and-insert as each bq × bk score tile is computed. After the final key tile, the queues are merged with warp shuffles to produce the row’s top-κ key indices and corresponding weights, which are normalized using the row’s final softmax statistics. The total cost is O(n2), matching the underlying prefill matrix multiplication (Appendix C.1). Empirically, this adds 6–8% to prefill wall time (Appendix C.3). Leiden partitioning is pipelined with the forward pass: as soon as layer L’s attention scores are available, its graphs are dispatched to asynchronous workers while layers L+1 , . . . continue executing (Appendix C.2). The only exposed latency is the final layer’s partition (0.37–0.45s across the Qwen3 family). We provide the fused top-κ selection complexity derivation, pipelined graph-partitioning schedule, component-level latency breakdown, and memory accounting in Appendix C. 

# 4 Experiments 

We evaluate CommunityKV along three axes: (1) accuracy compared to sparse attention baselines on long context benchmarks, (2) end-to-end throughput and peak GPU memory, and (3) ablation studies over key design parameters. Unless otherwise noted, we fix κ = 8 , λ = 0 .5, exclude the first 10 sink tokens from graph construction, and maintain one independent graph per query head. All models use greedy decoding (single run, deterministic) with a maximum of 128 generated tokens and YaRN RoPE scaling [30] to extend the model context. To ensure a fair comparison, we tune γ to produce a mean community size of 16, matching the baselines’ retrieval granularity.

BABILong We additionally evaluate on BABILong [20] QA1–QA5, a multi-hop reasoning bench-mark requiring retrieval of 1–5 supporting facts from long context inputs. 

RULER We further evaluate on RULER [17], a configurable long-context benchmark spanning retrieval, multi-hop tracing, aggregation, and question answering.

4.2 Long context understanding Graph-based retrieval vs. KV eviction Both CommunityKV and GraphKV construct sparse graphs from attention scores, but differ in how they use the graph: GraphKV evicts tokens permanently, while CommunityKV retrieves dynamically. To isolate this distinction, we compare the two on LongBench v2 with Qwen3-8B, sweeping GraphKV’s budget from 4k to 32k tokens (Table 2). GraphKV requires an 8× larger budget (32k tokens) to reach 22.5% accuracy, while CommunityKV achieves 31.1% with only 4k tokens, nearly matching the dense baseline. This confirms that semantic structure should guide dynamic retrieval rather than permanent context deletion.

4.3 Computational efficiency 

We measure end-to-end throughput and peak GPU memory for 32,768-token generations at 64k and 128k input contexts across Qwen3-4B, 8B, and 14B on an NVIDIA H200 (Table 5). Under the per-query-head configuration used for the primary accuracy evaluation, CommunityKV achieves 

1.08 –1.25 × full-request speedup. Graph and centroid storage is 52–82% of KV-cache size, and total peak memory is 17–29% above dense. Query-group aggregation reduces auxiliary storage to approximately 12–15% of KV-cache size and peak-memory overhead to 0.5–8.5%, while increasing full-request speedup to 1.39 –1.71 ×. Throughput gains increase with context length for every model size. Query-group aggregation nearly matches per-query-head accuracy in the aggregation ablation (31.8% versus 32.0%; Table 6), making it the practical accuracy–systems tradeoff.

Graph aggregation In grouped-query attention (GQA) architectures, query heads share KV heads. We test three granularities for graph construction: per-query-head (default), query-group (one graph per KV group), and layer-wise (one graph per layer). Per-head (32.0%) and query-group (31.8%) perform comparably, while layer-wise collapses to 21.5%. Query-group aggregation is a viable memory-saving alternative. 

Sink tokens Excluding sink tokens from the graph and always retrieving them (32.0%) outperforms including them in the partition (31.3%). Sinks attract attention from nearly all positions, creating high-degree hubs that bridge unrelated communities. 

Isolating the contribution of Leiden We compare Leiden with two controls on the identical weighted graph: the connected-components control removes edges below a calibrated threshold and uses the surviving components as retrieval groups, while the top-k-neighborhood control seeds retrieval at the highest-scoring tokens and expands each seed by one graph hop to fill the budget. Both controls are calibrated to match CommunityKV’s mean group size of 16. CommunityKV outperforms both at every budget and model scale (Table 7), isolating the benefit of Leiden from graph construction. 

# 5 Conclusion 

We presented CommunityKV, a training-free framework that formulates sparse attention as dynamic community detection on a token graph induced from QK ⊤ scores. Partitioning this graph with the Leiden algorithm during prefill yields communities that serve as the retrieval unit during decoding, with sub-linear O(√n d ) cost per step. Limitations and future work Our greedy community assignment freezes prior assignments, which may cause partition drift over very long generation horizons; periodically re-partitioning every √n

steps mitigates this at amortized O(√n log n) cost per step, but adds latency in practice. The edge approximation during decoding is restricted to the retrieved set, so true top-κ keys outside retrieved communities are missed, and retrieval recall affects the quality of incremental updates. Unstructured graphs and isolated-span tasks may also limit whole-community retrieval. These limitations suggest several natural extensions of the framework. First, incremental Leiden refinement [24], performing local moves in the neighborhood of newly inserted tokens rather than single-node greedy assignment, could better maintain partition quality during decoding over longer horizons. Second, the hierarchical structure that Leiden naturally produces via its aggregation phase could enable O(d log n) retrieval at longer contexts where even O(√n) communities become expensive to score. C.1 Fused top-κ selection 

We construct the initial sparse graph by identifying the top-κ keys for all n queries simultaneously, fusing this selection directly into the FlashAttention kernel with a WarpSelect-style register-resident selector [18]. As the kernel computes scores for each bq × bk tile of queries and keys, each GPU thread maintains a sorted queue of κ candidates using compare-and-insert operations. Each candidate contains a pre-softmax scaled QK logit and its key index. Block-level candidates are accumulated with warp shuffles to emit the row’s top-κ indices and corresponding weights, which are normalized using the row’s final softmax statistics. The total complexity aggregates two costs: 1. Block-level sorting. Every score in the causal attention matrix is tested against a queue threshold, requiring O(n2) work. In the worst case, each score triggers an insertion requiring at most κ compare-and-insert operations, giving O(κn 2) work. 2. Global top-κ reduction. Producing κ outputs requires a fixed-depth shuffle reduction for each selected candidate. Across all query rows, this costs O(κn ).Combining these terms, the total graph construction worst case complexity is: 

O κn 2 + nκ  = O(κn 2). (8) Because κ is fixed in our experiments, this scales as O(n2), matching the underlying causal prefill computation and adding no asymptotic overhead. This bound is pessimistic because an insertion occurs only when a score exceeds the queue’s current κ-th largest value. Total CommunityKV prefill overheads are 7.8% for Qwen3-4B, 7.7% for Qwen3-8B, and 7.2% for Qwen3-14B on 131k-token inputs (Table 10). 

C.2 Pipelined graph partitioning 

Naively, Leiden partitioning would extend the prefill critical path by the sum of per-layer partition costs. We instead dispatch each layer’s partitioning to asynchronous workers immediately after its attention scores are computed, allowing it to run in parallel with the FFN of the same layer and the attention of subsequent layers (Figure 4). Because the FFN and following layers’ attention together exceed the per-layer Leiden cost, all layers except the last have their partition cost fully masked. The exposed latency is therefore the cost of partitioning a single layer’s graphs, which we measure at 0.37–0.45 s across the Qwen3 family on an NVIDIA H100 (Table 10). This corresponds to 2–3% of total prefill wall time on a 130k-token input.

Per-graph footprint Each graph stores at most |E| ≤ 2nκ (1 + κ) edges (Section 3.1). Storing edge weights in bfloat16 with 32-bit indices yields a per-graph cost of 8|E| bytes. At n = 100 ktokens with κ = 8 , we empirically observe |E| ≈ 1.15 M edges and a per-graph footprint of ∼9 MB; the observed footprint is <20 MB at κ = 8 across all sequence lengths in our evaluation. 

Aggregate footprint Without aggregation, a model with L layers and H query heads maintains 

L·H independent graphs. For Qwen3-14B ( L = 40 , H = 40 , with 8 KV heads per layer), this is 1600 per-head graphs. Under query-group aggregation (one graph per KV group, ablated in Section 4.4), this reduces to L · HKV = 320 graphs. At 100k tokens with κ = 8 in bfloat16, the aggregate footprint is <15 GB without aggregation and <3 GB with query-group aggregation, compared to ∼16 GB for the dense KV cache at the same context length and the 28 GB Qwen3-14B model weights in bfloat16. Graph memory under query-group aggregation is therefore a small fraction of total model state. 

Centroid storage Community centroids are stored in d-dimensional bfloat16. With O(√n) com-munities per graph (Appendix A), centroid storage is O(√n d ) per graph and is dominated by the edge storage above at all evaluated context lengths. 

Comparison to dense KV cache The dense KV cache scales as 2L · HKV · n · dhead in bfloat16. For Qwen3-14B at 100k context, this is approximately 16 GB, roughly an order of magnitude larger than the graph footprint under query-group aggregation.
