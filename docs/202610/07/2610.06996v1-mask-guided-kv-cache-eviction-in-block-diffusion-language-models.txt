Block diffusion language models keep a large key-value (KV) cache throughout generation and attend to it at every denoising step, limiting both memory capacity and generation speed. Reducing these costs requires deciding which past tokens to use for denoising the current block (selection) and which to keep in memory for future blocks (eviction). We propose MaskAhead, a training-free method that solves both tasks with a single mask-query-based ranking mechanism. Current-block masks guide selection, while probes of upcoming masked blocks guide eviction. Both rank KV entries by their estimated contribution to the attention output. Our quantized variant, Q-MaskAhead, computes selection and attention directly from low-bit KV, largely preserving the selected entries. Experiments on Fast-dLLM-v2, DreamReasoner, and LLaDA2.0-mini cover long-generation reasoning, long-prompt question answering, and needle-in-a-haystack retrieval. On long-prompt QA, MaskAhead reduces KV memory by 9 .5× on average with a 1.2-point mean F1 loss relative to dense inference. Q-MaskAhead increases the reduction to 20 .1× with a 2.3-point mean F1 loss. In a batch-32 systems profile, MaskAhead achieves 1 .23 × end-to-end and 1 .68 × decode-stage speedups over dense inference. 

## 1 Introduction 

Diffusion language models (dLLMs) generate text by repeatedly denoising masked positions, replacing the token-by-token autoregressive loop with parallel decoding [Lou et al., 2024, Sahoo et al., 2024, Nie et al., 2025, Ye et al., 2025]. This parallelism accelerates generation, but over a long decoding horizon it weakens dependencies among jointly predicted tokens [Wu et al., 2026b, Kang et al., 2026]. Current systems therefore use block diffusion, generating blocks in sequence while denoising the tokens within blocks in parallel [Arriola et al., 2025, Wu et al., 2026a, Bie et al., 2025]. Block diffusion restores a causal prefix and with it a key-value (KV) cache: after a block is finalized, later blocks reuse its keys and values without recomputation. As the prompt and response grow, every new block retains more KV entries, and every denoising step reads a longer prefix. Long-context inference pays twice for the same history: in resident cache memory and in repeated cache reads. Recent methods target the second cost. They use mask-token queries to predict the attention distribution of subsequent denoising steps and read only the most relevant prefix entries [Kwon et al., 2026b,a]. This reduces cache reads but retains the full history. Reducing memory instead requires irreversible eviction: deciding which entries future blocks will not need. Block diffusion permits a query probe before future blocks are generated: masked positions expose model-derived queries conditioned on the known prefix. We use these queries as a forecast for eviction, while current-block queries select temporary reads. The forecast cannot include tokens that intermediate blocks will later finalize. MaskAhead tests whether this forward-looking evidence helps most where retention is irreversible and storage is tight. 1arXiv:2610.06996v1 [cs.LG] 4 Oct 2026 2 Related Work 

Sparse reads in block diffusion. An exact prefix cache makes block diffusion practical, but its full contents are read repeatedly during denoising. SparseD [Wang et al., 2026b] exploits attention patterns shared across steps, while FlashBlock [Chen et al., 2026] reuses stable attention outputs outside the active block. MAGE [Kwon et al., 2026b] instead uses attention from the fully masked first step to select one prefix subset for the remaining denoising steps. These methods reduce cache reads across denoising steps but keep the full prefix resident on the GPU, leaving its memory unchanged. The attention-trace analysis in Figure 1 tests how long a read set remains informative. We use it as a mechanistic diagnostic, not as evidence that a future-mask probe beats alternative query sources. HERALD [Kwon et al., 2026a] offloads the full cache to host memory and retrieves a selected subset for each block. It uses one representative mask query to reduce the cost of selection. Offloading lowers GPU-resident memory but retains the full cache in host memory and incurs retrieval and transfer costs. MaskAhead instead physically removes entries, enforcing a storage budget after each eviction. GroupKV [Wang et al., 2026a] extends block-dLLM retrieval with hierarchical group selection and predictive prefetching across cache tiers. 

Eviction in diffusion models. Eviction has been studied for full-attention dLLMs, which revisit the entire prompt at every denoising step. Sparse-dLLM [Song et al., 2026] chooses entries using saliency that persists across steps, while MaskKV [Huang et al., 2026] ranks prompt entries by mask-query attention and assigns budgets per layer and head. Block diffusion exposes masks only in the active block and continually appends finalized output to an exact cache. This requires recurrent, forward-looking eviction. We test whether future masks provide a robust look-ahead signal and turn it into a practical strategy. 

Estimating what future tokens will need in AR generation. AR eviction methods must make retention decisions without the queries that future tokens will form. StreamingLLM [Xiao et al., 2024] protects attention sinks and recent tokens, while H2O [Zhang et al., 2023] accumulates past attention to preserve heavy hitters. Our eviction policy protects initial and recent positions, and ranks the remaining entries with future-mask attention. LookaheadKV [Ahn et al., 2026] learns soft lookahead tokens and adapters to estimate future token importance. It requires additional data and model-specific optimization. Training-free methods instead approximate the missing queries: Expected Attention [Devoto et al., 2025] extrapolates their distribution from past hidden states, while LAQ [Wang et al., 2025] and DapQ [Tian et al., 2026] construct positional surrogates. CAOTE [Goel et al., 2025] ranks entries by attention-output sensitivity, combining attention weights with value vectors. Its H2O instantiation uses accumulated past attention. MaskAhead uses value-aware scores with two query horizons: current-block masks for temporary reads and upcoming masked blocks for persistent retention. A no-write probe supplies the future queries, and recurrent compaction enforces the storage budget.

Contributions. Our main contributions can be summarized as follows: 

• Two decisions, two query horizons. We distinguish temporary reads from irreversible retention and identify the query evidence each decision requires. 

• Future masks guide permanent retention. MaskAhead combines current-block read selection with future-mask probes and value-aware eviction, physically enforcing a persistent KV budget. 

• Four-bit storage preserves selection. We disentangle selection, eviction, and precision. The ranking diagnostic finds 97.44% read-set and 97.65% retention-set overlap between four-bit and bf16 storage, supporting Q-MaskAhead’s compact persistent cache without a bf16 shadow copy. 

• Validation across three models and distinct workloads. Experiments on Fast-dLLM-v2-7B, DreamReasoner-8B, and LLaDA 2.0 cover long-generation reasoning, long-prompt QA, and needle-in-a-haystack (NIAH) passage retrieval. MaskAhead achieves the highest F1 among evicting methods in all six main QA settings, including one tie, while reducing KV memory by 9.5× on average.

Decisions from four-bit storage. Q-MaskAhead stores keys and values at four bits and computes rankings from that stored representation without a bf16 shadow cache. Keys use asymmetric per-channel quantization over groups of 32 positions. Values use per-token groups of 32 channels with fp16 metadata. Incomplete key groups remain bf16, and the scoring pass unpacks stored values when needed. After eviction, complete surviving key groups are copied bit for bit and partial groups are regrouped. The four-bit result therefore tests selection, retention, and attention with a compact cache rather than quantizing a preselected bf16 cache. For long prompts, the retention mechanism can be applied after full prefill or during prompt processing. We compare full prefill, chunked prefill, and question-probe heuristics in Section 5.5.

Expected Attention illustrates why the retained-token budget is insufficient for comparing memory. The comparison must account for auxiliary state as well as retained entries, rather than interpret eviction itself as a guarantee of compression. Long-prompt QA exposes a different pattern: MaskAhead and DapQ are close at matched KV memory, while both preserve substantially more quality than historical-attention retention. Q-MaskAhead further reduces the storage cost of surviving entries, giving the smallest KV footprint in every main model/task setting. 5.3 Precision changes the memory and quality budgets 

Eviction and quantization reduce different parts of the storage cost: the number of resident entries and the bytes used to represent each entry. Their combination gives the smallest measured KV footprint in the main task matrix (Table 6). On MATH-500, four-bit storage adds a 2 .48 × KV-memory reduction over bf16 MaskAhead at a 0.6-point accuracy cost. The reduction is smaller than the nominal ratio between bf16 and four-bit payloads because the reported KV also includes method state, not only compressed entries. The quality cost of stored precision is task dependent. Untransformed K4V4 loses more F1 on Fast-dLLM HotpotQA than on the other main QA settings, while the rotated-and-centered key variant recovers much of that gap at unchanged KV memory (Table D.3). This comparison shows that the quantization representation matters within the same storage budget, although it does not separate the effects of rotation and centering. Across the six main QA settings, Q-MaskAhead reduces KV memory by 20 .1× on average at a mean 2.3-point F1 loss relative to dense inference. High ranking overlap is insufficient to certify quality preservation. The recording-only diagnostic finds over 97% overlap for both reads and retention, yet the generated answers remain sensitive to precision (Section D.3). Even unchanged sets use perturbed keys and values in attention, and set overlap does not measure the importance of the entries that differ. The budget sweeps expose a separate quality lever: more reads can improve answers without enlarging the persistent cache (Figure 5). At fixed retention, increasing the MATH-500 read floor brings accuracy close to dense inference while KV memory remains near the same level. HotpotQA also benefits from more reads, but the QA tasks have different read-fraction orderings (Table B.4). Thus, the storage budget need not dictate one read budget for every workload. These within-policy controls distinguish errors caused by limited access to surviving entries from the consequences of deleting entries, without establishing a global frontier over all baselines. 

5.4 Batch-profile memory and execution time 

The systems pilot separates smaller storage from faster execution (Figure 3). K4V4-only storage substantially reduces resident KV but does not reduce the recorded batch-32 decode time. Quantization alone leaves the full logical prefix available to the attention procedure, whereas MaskAhead also reduces the entries gathered for repeated denoising and removes entries from persistent storage. At batch 32, MaskAhead and Q-MaskAhead reduce KV memory by 85.1% and 89.9%, respectively. Their recorded decode-time ratios relative to dense bf16 are 1 .68 × and 1 .64 ×, while complete-batch ratios are smaller at 1 .23 × and 1 .20 ×. 5.5 Retention heuristics for long prefill 

The QA comparisons above use full prefill: the model processes the complete prompt before applying retention, once the question is available. This reduces KV memory during decoding. When the prompt is much longer than the response, however, the memory peak occurs during prefill. We therefore apply the same retention framework with three prefill heuristics: 

• Full prefill: retain the prompt cache until prefill completes, then compress it for decoding. 

• Chunked prefill: process the prompt in 512-token chunks and evict entries between chunks. 

• Question probe: use question-conditioned probing to rank entries for early retention during prompt processing.

## 6 Conclusion 

MaskAhead combines current-block read selection with future-mask-guided retention in block diffusion. It achieves the highest F1 among evicting methods across all six main QA settings, including one tie, with an average 9 .5× reduction in KV memory and a 1.2-point mean F1 loss relative to dense inference. Q-MaskAhead extends the average reduction to 20 .1× with a 2.3-point F1 loss. Matched controls favor future-block masks over current-only and pseudo-token probes. Value-aware scoring has the highest point estimates in the score factorization, while paired quality intervals include zero. ## E Prefill Policies and Long-Prompt Retrieval 

We compare full prefill, chunked prefill, and question probe, followed by their interaction with four-bit storage and passage retrieval. Unless stated otherwise, the prefill comparisons measure the maximum KV memory over prompt processing and generation. 

E.1 Prefill heuristics 

Full prefill applies retention after processing the complete prompt. On HotpotQA, it reaches 38.41 F1 with a maximum KV memory of 0.999 relative to dense bf16. Question probe uses question-conditioned evidence for early retention and reaches 37.16 F1 at 0.144 KV memory. Chunked prefill evicts between 512-token chunks and reaches 26.90 F1 at 0.185 KV memory. All three leave the same normalized resident cache of 0.107 after the response, despite their different memory requirements during prompt processing. These heuristics change ranking and retention timing together. Question probe also reaches 24.10 F1 at 0.125 KV memory on NarrativeQA and 15.35 F1 at 0.129 on MuSiQue.
